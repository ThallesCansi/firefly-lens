# Phase 4 - integration with real Brazil data

The initial branding/theme work was completed against the simulated-data application. Before publication, main received PR #3 (8799ed0), connecting the real NASA FIRMS Brazil pipeline. The Phase 4 branch was merged with that update and the documentation/UI adapters were reconciled before publication.

## Preserved work

The Python pipeline, all real data files, source adapters, harmonization calculations and scientific tests are preserved exactly from the incoming main. The original Lume component is unchanged. CSV export functions are preserved from the new real-data implementation; only the SVG presentation delegates to the annotated renderer.

## Updated integration

- Real-data map cells retain their weighted counts, sensor-specific sizing and Brazil outline while theme changes restore the same layers on the existing map instance.
- Headers retain original Lume + Lens, Light/Dark/System persistence and before-paint initialization.
- Method keeps three keyboard/hash-accessible tabs and KaTeX/MathML equations. Harmonization now describes the offline NB2 model, 0.25-degree grid, Aqua-equivalent units, observed-through-2025 rule, modeled continuation, weighted aggregation and uncertainty.
- Original real-data methodological steps and limitations are retained in RealDataNotes.ts. Validation statements are attributed to the committed pipeline outputs, not fabricated or newly measured by this UI phase.
- Monthly medians use the 2003-2025 reference; complete-month ranks, partial months and observed/modeled distinctions are preserved. Local daily MAD flags remain separate from conceptual seasonal z-scores. Python reference-calendar percentiles are acknowledged but are not described as displayed frontend indicators.
- FRP is explicitly absent from the current browser tiles, rather than represented using obsolete simulated fields.
- SVGs identify NASA FIRMS Brazil, Aqua-equivalent units, processing, period and actual export time. Tests check retained values and XML escaping. Modeled/partial status is included in cell descriptions.

## Validation

Vitest passes 16 tests (the incoming scientific/data tests plus Phase 4 theme and SVG tests). TypeScript, repository lint and production build are rechecked after conflict resolution. The theme/browser test is updated to the real-data schema and source labels. Original Phase 3 regression covers map drawing, analysis, dates, layers, search and CSV.

Current captures are generated by scripts/verify-brand-themes.mjs. Initial simulated-build validation is retained separately in initial-simulation-validation.md as historical evidence, not as a statement about the active source.

## Reproduce

Use pnpm install --frozen-lockfile, pnpm dev, pnpm test, pnpm lint and pnpm build. On PowerShell use pnpm.cmd if script execution is disabled. Open / and /method. Browser QA optionally uses Playwright and Chrome, with PLAYWRIGHT_MODULE pointing to an installed module URL.

The main publication was explicitly requested by the user after initial local delivery. No Python model was retrained or modified as part of this integration. Dataset availability is the committed metadata period, not a claim of live ingestion. See harmonization/docs/METHODOLOGY.md and the Method reference links for the scientific method and its limitations.
