# Phase 3 — Map-first exploration

The implementation runs locally on `feature/map-first-experience`. No push, merge or deployment is performed.

## Architecture and preservation

Installed versions: Next.js 16.4.6, React 19.3.0, MapLibre GL JS 6.18.0, TypeScript 5.9.3 and Tailwind CSS 4.3.3. Implementation follows the installed Next.js guides for pages, client components, route handlers and cache components.

`LensApp` owns the draft area, committed analysis area, Explore/Analysis mode, UTC map period, historical range and visible sensors. The map instance remains mounted across both modes. `AnalysisContent` reuses the original history grid, daily calendar, sensor comparison, day details and exports. Its historical query mounts only after confirmation and retains its result while closed. A different committed area resets the content, preventing old results from appearing under the new area's name.

`HotspotMap` retains the original MapLibre layers and rectangle selection. It adds zoom controls, free scroll/touch navigation, per-sensor visibility, navigation destinations, reset and resize handling. Drawing disables conflicting gestures and zoom buttons; Escape, Navigate or the active drawing button cancels it. The existing normalizer still limits a rectangle to 12° per side; coordinate entry rejects larger bounds. The map camera is never a historical-query dependency.

`TopNavigation`, `MapToolbar` and `MapLayerControl` provide reusable workspace navigation and controls. `LocationSearch` and `/api/geocode` provide explicit place search, fitting the returned geographic extent when available without selecting it. `TemporalControl` and `useMapHotspots` query only the chosen month or day in the chosen rectangle. The new map query hook reports failures separately from an empty result; it does not change the scientific source adapter. Monthly selection highlights the month and updates the seasonal comparison. Daily details appear only when a day is explicitly selected.

No harmonization, calibration, anomaly algorithm, simulated source, scientific type, export algorithm or Python module changed. The original `FireCalendar`, `SensorCompare` and `DayDetail` are reused unchanged. The only history-grid API additions are optional month-selection and selected-month props. Raw detection counts remain distinct from independent fires and harmonized activity; each sensor chart retains its own scale.

## Flow and layout

1. `/` or `/lens` opens a viewport-height map beneath a search header. Toolbar is on the left, sensor switches at the upper right, temporal controls below and map attribution at the bottom edge.
2. Search navigates only. Draw a rectangle, apply coordinate bounds, or choose a preset from Coordinates to select an area.
3. The area card displays its bounds and **Analyze Area**. Editing updates the draft and returns to Explore. Confirmation starts or resumes historical analysis.
4. Desktop uses a right pane with independent scrolling and an Expand option. Mobile uses a bottom sheet, leaving a visible map above. The analysis presents the range, selected-month comparison, historical monthly grid, daily calendars, sensor details/comparison and exports.
5. Choose a month or day to update the map. Close the analysis to return to exploration with its context retained.

The original introduction is preserved at `/about`; methodology remains at `/method`.

## Run and reproduce

Node 20.9+ and pnpm 10.34.9:

```sh
pnpm install --frozen-lockfile
pnpm dev
pnpm test
pnpm lint
pnpm build
pnpm start
```

On Windows with PowerShell script execution disabled, use `pnpm.cmd`. If Next route types have not yet been generated, run `pnpm exec next typegen` before a standalone `pnpm exec tsc --noEmit`.

Browser QA uses an optional Playwright installation and Chrome; it does not add a runtime or development dependency to this repository. With Playwright resolvable locally, run `node scripts/verify-map-workspace.mjs` against the running app. Alternatively set `PLAYWRIGHT_MODULE` to its installed `index.mjs` file URL. Optional `PREVIEW_URL` changes the origin; `PLAYWRIGHT_CHANNEL` changes the installed browser channel.

## Limits

- Data remain simulated, 2001–2025; there are no real global detections or live observations. Before selecting an area, the map intentionally has no detection points.
- VIIRS availability begins on 20 January 2012. Calendar/map controls identify unavailable periods. Raw point density is not a fire count or burned area.
- Historical analysis covers the full source record for calibration and seasonal baselines. The chosen historical range filters presentation/exports; month/day selection controls the map. Camera movement and sensor visibility never change the baseline.
- Raw hot spot CSV retains the existing 36-month limit. Other scientific exports remain available.
- Photon public demo service allows moderate use and may throttle or change availability. The guard is per server process, not a distributed quota. Configure `PHOTON_URL` for a private provider at larger scale. Search data are sent to that provider only on submission; coordinate navigation is resolved locally.
- CARTO tiles and place search need a network connection; WebGL is required for map rendering. Coordinate selection and analyses remain accessible when WebGL is unavailable. Browser tests cover Chrome desktop and mobile emulation, not every physical touch device or browser.
- No polygon drawing or advanced temporal animation was added. Context is retained within the workspace session, not persisted after reload.
